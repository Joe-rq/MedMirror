## 1. 课程与比赛分别验收什么

|---|---|---|
| 自主开发 | 规约、状态、CLI、依赖锁、CI、PR 流程 | 人认可的标准发现包、真实反例定标、业务验收 |
| 任务一：发现差异 | 1 病例 × 3 模型 × 3 问法 × 3 重复的原文 | 正确分组、截断处理、人工核对；单病例重复不是多个独立临床场景 |
| 任务二：识别 Bias | 不预设偏见、保留专业复核边界 | 对具体主张的证据、适用人群、疾病阶段、安全性核查与医学复核 |
| 任务三：解释 Bias | 中性与显式问法；有界证据追问计划 | 可被支持或反驳的假设及对照；模型自述原因不能作为因果证明 |

既有 CLI、单病例收敛、版本化和诚实报告边界应保留。最大的偏移是先推进采集与自动化，却未先完成一份人工审过的发现包。比赛不以自动化程度或 Bias 数量评分。

## 4. 两人分工与交付顺序

建议你负责研究标准和最终结论，伙伴负责实现与复现。两人共同抽查语义；专业医学判断另找复核人员。伙伴可先修确定性的聚合、数据保护和离线回放，不必等医学判断全部完成。

### 第一步：你交出一份标准发现包，伙伴同步修报告（优先当天）

你的交付：

1. 从已有 27 条选同一模型中性 / 中医镜像 / 西医镜像各一条，逐句标注，做一份完整示范；这是定标样本，不能当作独立验证数据。
2. 与伙伴分别核对全部 27 条的提及、态度对象、条件、来源和截断；保留分歧与裁决记录，不把未审数据称金标准。
3. 把示范、负例、检测入口落到 `specs/examples/standard-finding.md`、`specs/examples/negatives.jsonl`、`scripts/check_calibration.py`（以上为拟建文件）。负例至少覆盖本计划表中的问题及未提及、失败、不一致结果。
4. 首份发现包括：研究问题、分组 n/N、支持与反例 trial_id、逐字引文定位、医学待复核问题、解释假设、限制。没有确认 Bias 也可成立。

伙伴的首个开发单元：修复 `scripts/report_exp003.py` 的分组聚合，增加 `--input` / `--output`，派生产物写新目录；补 `tests/test_report_exp003.py`。保持原始回答与旧报告不变。复用 `load_jsonl`，不要直接照搬只有总体汇总的 `aggregate`。

### 第二步：伙伴实现评分与运行护栏，你准备医学复核包

伙伴按确认的标注标准升级提取器版本，增加对象/条件/不确定状态和引文定位；保存新旧提取结果，展示逐条差异。用留出的未参与规则修改的标注样本检查，记录误报漏报，不能只汇报测试通过。

随后拆出 `src/medmirror/runner.py` 与 `budget.py`，复用 provider 请求构造，但用可注入的假网络客户端测试预算、重试、恢复、配置变化、截断与未执行状态。测试历史答案不被覆盖、未知费用不当零、恢复不重复成功调用。超时是否已计费不明时保留预留并标待核账。

你准备每个候选主张的复核表：原文、具体主张、疾病/阶段/人群、证据出处和定位、来源是否支持、反证、安全问题、复核人/日期/状态。检索医学资料时再核对权威原文；本轮代码审计不代替医学核查。

验收：你和伙伴能解释每个评分的原文依据；无法判定的项目明确待复核；下一次真实调用受到代码预算约束。

### 第三步：再执行 plan/001 的有限追问

新增 `src/medmirror/followup.py`：输入固定版本的基线与提取结果；固定顺序选择；每模型最多两次、全轮最多六次；无候选、失败、预算不足均正常结束；完整保存 parent_trial_id 和停止理由。接入第二步账本，不另建第二套调用逻辑。

原有“请提供上一条建议的依据”只能检验来源补充与前后表述变化，不能验证训练数据、检索失败或安全策略的底层原因。

为了更好回答任务三，可另拟一个受控补充实验（须确认新协议及预算后才运行）：

- 假设：显式触发能改变自然呈现，但不一定改变推荐条件。
- 干预：已有三种问法提供提示效应的初步材料；若进一步做资料补充，使用同一问题、同一模型设置和新独立会话，对照“无资料 / 固定已核实资料”，预先登记测量指标与相反结果。
- 解释边界：资料后改变回答，仅支持“本条件下呈现可改变”；不能证明原模型不知道、训练偏见或搜索召回不足。没有变化也报告。
- 不为凑实验而扩大病例或堆建 RAG。额外研究协议保持 draft，不能混入 v1.3。

### 第四步：冻结提交包与演示
