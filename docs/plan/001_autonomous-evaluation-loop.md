# Issue 001：自主评测闭环与有限追问

## Context

前序工作已经完成真实 API 基线执行，但这部分是在 Issue 入口建立前推进的，作为“已部分实现的探索材料”登记。当前系统能读取配置、执行基线、保存原始回答和 usage，并生成离线提取报告；还不能根据结果自主决定是否追问，也不能生成完整的发现包。

## 现状

- `scripts/run_exp003_baseline.py`：支持 27 条基线、有限重试、断点恢复和原始 JSONL。
- `src/medmirror/protocol.py`：支持路径提取、状态区分和失败分母。
- `scripts/report_exp003.py`：支持离线提取、usage 汇总和已登记价格下的成本估算。
- `docs/experiments/exp003-baseline/result/`：已有 27 条真实回答，27/27 有最终正文。
- 尚无 `parent_trial_id` 追问记录、追问选择理由、预算预留账本和最终发现包。

## Goal

在不改变已冻结基线结果的前提下，增加一个可恢复、有限额、可解释的自主追问闭环：系统先读取基线提取结果，按固定规则选择候选 trial，最多追问两次/模型、全轮最多六次，并输出带原文证据和停止理由的发现包。

## 实体与关系

```text
Protocol ──< Trial ──< Extraction
                  └──< FollowupTrial（parent_trial_id → Trial）
Trial / Extraction ──< Finding
Run ──< BudgetLedger
```

- `FollowupTrial` 必须保存 `parent_trial_id`、触发规则版本、完整消息、最终回答、usage、错误和停止原因。
- `Finding` 只能表达观察到的呈现差异，不能自动写成医学 Bias 结论。
- `BudgetLedger` 记录预留、实际 usage、估算费用、失败重试和剩余额度。

## 信息流

| 阶段 | 输入 | 输出 | 约束 |
|---|---|---|---|
| 1. 读取基线 | `trials.jsonl`、`extractions.jsonl`、协议版本 | 候选路径集合 | 只读取同一协议版本，失败不进有效分母 |
| 2. 候选选择 | 中性/镜像路径状态、原文定位 | 每模型最多 1 个候选路径 | 规则固定、选择理由可复现，不按回答“精彩程度”挑选 |
| 3. 预算预留 | 候选数量、模型价格、上限 | `BudgetLedger` 预留记录 | 预算不足立即停止，不发起超额调用 |
| 4. 有界追问 | parent trial、统一追问模板 | `FollowupTrial` | 每模型最多 2 次，全轮最多 6 次，不递归 |
| 5. 发现生成 | 基线 + 追问记录 | `findings.jsonl`、报告、复核清单 | 引用 trial_id 和逐字证据，标记未经专业复核的内容 |
| 6. 回放 | 已保存记录 | 同版本报告 | 回放不重新请求模型 |

## 固定触发规则

第一版只触发以下情况：同一模型在中性变体中某路径全部未提及，而明确询问该路径的镜像变体至少一次提及，并且对应原文可定位。每个模型按固定路径顺序最多选择一个候选。

统一追问：

> 请说明你上一条回答中涉及的治疗建议或限制的依据；如能提供具体来源，请列明来源名称、年份及其支持的具体表述。无法确认的部分请明确说明。

## 验收标准

- [ ] 对当前 27 条基线能确定性地产生候选集合；无候选时正常结束。
- [ ] 追问记录包含 `parent_trial_id`、规则版本、完整消息、usage、状态和停止原因。
- [ ] 成功追问不会因重复运行而重复调用；失败可有限重试并保留失败记录。
- [ ] 单模型最多 2 次、全轮最多 6 次，预算不足时不发起下一次调用。
- [ ] 生成发现包时保留支持与相反证据，区分未提及、反对、条件支持、推荐。
- [ ] 离线回放不调用模型，报告结果可重算。
- [ ] 本地规则测试、协议反例检查和一次真实小范围追问均通过。

## 风险与取舍

- 当前三个供应商的思考参数不同；追问阶段沿用 v1.3 的供应商级参数，并记录偏离，不把参数差异解释成医学差异。
- 自动提取可能误把否定或条件句识别成推荐；必须先补回归样例，再启用真实追问。
- 追问结果可能出现新医学主张；系统只负责归档和标记，不自动核实临床正确性。
- 专业复核人员尚未到位，因此最终输出保持“候选待复核”措辞。
