# 黑客松后路线图：证据等级 → 规模 → 输出

2026-09-13 黑客松作品已提交（GitHub 公开仓 https://github.com/Joe-rq/MedMirror ，镜像——CNB 仓库为真相源，同步状态见 `state/board.md`；评委导航 `docs/reviews/judge-entry.md`）。评审期后项目价值锚点从"给评委看"换回 intent.md 的目标受众——评测研究者。对评测研究者而言，当前三个关键问题的答案是：提取器语义**已按缩窄口径定标**（1 条完整标注 + 9 条裁决 + 14 条抽查信任扩展，局限声明见 `specs/calibration/fp-fn-report.md`）、复核**未执行**、样本**撑不住稳定性结论**。因此后续主线不是加功能，而是把已有 27+4 条数据的证据等级提上去，再放大规模，再对外输出。

主人 2026-09-13 确认三项前提：
- **定位**（四项并存，主次按本路线图排）：论文/技术报告、开源工具、持续参赛、自用学习。
- **人工环节**：#5 复核人去找。
- **定标口径**：#11 已按缩窄口径关闭（2026-09-12），14 条"抽查后接受"信任扩展**赛后不补做**严格独立标注，局限声明在一切对外输出中保留。

四定位共享一条主线，不存在资源分裂：论文吃阶段一+二的数据、工具吃阶段二的模板化、比赛吃阶段二的新数据与故事、自用贯穿始终。

## 4. 风险与权衡

- **口径约束（硬性）**：新病例数据沿用同一缩窄定标口径（机器对照 + 抽查 + needs_review 交人工），不因扩规模加码也不放宽；14 条信任扩展的局限声明在一切对外输出中保留。
- **复核人找不到**：claims 永久保守；论文转向方法学贡献（呈现差异评测框架本身），不硬凑医学结论。
- **新病例暴露提取器缺陷**：修入 v3 并保持 v2 冻结对照；不回改已发布报告，新版本另行生成。
- **四定位人力冲突**：砍比赛 demo 打磨，保论文数据与工具可用性；比赛叙事直接复用阶段二产物。
- **预算口径**：扩规模前重新确认 50 元总额是否仍有效、开发工具费用是否计入（real.md 未决项）。
- **开源后的协议变更管理**：外部贡献者提出协议/评分修改时，沿用"协议和评分变更进入新版本"红线，拒绝就地改尺子。

## 5. 范围外

- 不宣称或暗示已确认医学 Bias（intent 红线，永久有效）。
- 不做多疾病大全、长期向量记忆、复杂多代理平台（intent 红线）。
- 不给患者诊疗建议；真实患者数据不入实验。
- 阶段二之外不再主动扩张工程功能（glm 零正文成因、step 截断专项实验仅在服务新协议时顺带）。
