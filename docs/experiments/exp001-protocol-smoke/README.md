# exp001 · protocol-smoke

状态：planned。日期：2026-09-09。类型：离线协议冒烟，不调用任何模型 API。

## 假设

如果首轮评测协议把原始回答、语义标签、引文、失败状态和分母分开保存，那么系统可以在没有付费模型调用的情况下发现最基本的评分错误，并且能回放生成报告。

## 输入

构造 6 条固定回答，覆盖：

1. 未提及某治疗路径；
2. 明确不建议；
3. 有条件支持；
4. 明确推荐但同时写风险；
5. 提到“指南”但没有可识别来源；
6. 调用失败，不应被当成未提及。

每条回答都带 `trial_id`、`case_id`、`model`、`prompt_variant`、`trial_index`、原文和状态。语义预期标签由人工写在 fixture 中，作为协议测试期望，不作为医学真相。

## 检查

- 能否从 finding 回到唯一 `trial_id` 和逐字引文。
- 未提及、反对、条件支持、明确推荐不会合并成一个推荐分数。
- 失败和截断不进入有效回答分母。
- 没有证据来源时不能生成“证据已核实”。
- 相反回答会出现在报告中。
- 同一输入回放报告不触发模型调用。
- 规则版本和 extractor 版本进入结果记录。

## 通过标准

所有上述检查都有机器可判的结果；至少一条故意错误的 fixture 能被测试捕获。报告显示有效分母、失败数和低置信／待复核状态。测试不得使用在线 API、密钥或真实患者信息。

## 不在本实验内

不比较三家真实模型，不判断医学合理性，不校准 LLM Judge，不实现自动追问，不建设展示页面。

## 结果

2026-09-09 完成。运行 `python3 scripts/run_exp001.py` 通过：6 条计划试次中 5 条有效、1 条模拟超时；失败没有进入有效分母。离线规则正确区分未提及、反对、有条件支持和明确推荐；“提到指南／研究”但没有可识别来源时，`evidence_mentioned=true`、`identifiable_source=false`。报告回放只读取 fixture 和 extraction，不调用模型。

第一次测试曾暴露两个问题：把泛词“年份”误判成可识别来源，以及没有覆盖“建议使用”这一明确推荐短语。修正规则和样本后，4 个契约测试全部通过。这个结果说明数据契约和基本反例可运行；不说明真实模型提取已经可靠，也不构成医学判断。
