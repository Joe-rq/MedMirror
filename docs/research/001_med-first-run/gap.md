## 一、它们做到的

### 当前可复用的能力

| 发现 | 状态 | 采用方式 |
|---|---|---|
| Trial 与完整原始 trace 分离保存 | 部分已有讨论方案 | 直接采用，原始回答不被聚合结果覆盖 |
| 多次 trial 观察随机性 | 部分已有讨论方案 | 首轮采用，但只报告描述性频率 |
| Rule-based + LLM grader | 可借鉴 | 规则先做结构检查，LLM 提取附原文并接受人工抽查 |
| Human review queue | 可借鉴 | 直接采用，候选差异进入待复核而非自动确认 |

### 只能借鉴的做法

| 做法 | 原因 |
|---|---|
| 医学正确性总分 | 团队暂无专业复核，且当前目标是治疗路径呈现差异 |
| 单一 Bias Score | 会掩盖未提及、反对和推荐的语义区别 |
| 大规模 benchmark 或复杂多 Agent | 超出当前时间与预算 |

### GitHub 参考优先级

1. **PhysicianBench**：最适合借鉴 `jobs/<batch>/<task>/`、完整轨迹、`--resume` 和多次运行的组织方式；它依赖 EHR/FHIR，不能直接照搬到本项目。
2. **RxSafeBench**：最适合借鉴医疗安全观察维度，尤其是禁忌、相互作用和隐性风险；它的专家过滤数据不适合作为我们首个病例的 ground truth。
3. **LiveMedBench**：最适合借鉴病例级 rubric 与人工 QA；它规模很大，当前只取其“每条标准可解释、可追溯”的思想。
4. **tracelens**：最适合借鉴人工与 LLM judge 的并列校准、κ、混淆矩阵和诚实分母；首版可以只用 JSONL，不引入 Langfuse。
5. **harness-evals**：最适合借鉴 EvalCase 的 token、cost、retry、metadata 和 baseline 字段；先复刻数据契约，不安装整套框架。

**「修起来要什么」这一栏最要紧。** 同样是「缺」，成本差一个数量级：

| 缺法 | 成本 |
|---|---|
| **能力已经有了，只是没接上** | 低成本高收益，优先做 |
| **能力本身就没有** | 要立项，另算 |

判「缺」的时候多走一步，去底层看看是哪一种。

## 二、它们没做的

### 当前空白

| 找过什么 | 结论 | 是哪一种 |
|---|---|---|
| 发现差异后自动决定是否追问，并受预算和次数双重约束 | 公开讨论中尚未形成项目内可运行规则 | 机会：先做一个有界分支 |
| 将预算预留、结算、重试和断点恢复作为评测状态 | 当前只有方案描述，尚无实现 | 机会：属于首版工程核心 |
| 没有专业人员时确认医学合理性或 Bias | 无法由自动评测替代 | 天堑：只能交付候选与复核包 |
| 中医／西医提示变体完全医学等价 | 无法保证 | 天堑：只能解释为提示影响下的呈现差异 |

这些项目共同没有替我们解决的部分是：如何在没有本团队医学专家、只有 50 元预算时，选择一个可复核的中西医呈现差异实验，并让系统自主决定是否追问。因此这仍然必须通过自己的离线实验长出来。

| 找过什么 | 结论 | 是哪一种 |
|---|---|---|
| | **无人涉足** ／ 有但不适用（说明为什么） | 没顾上做 ／ 做不到 |

⚠️ **空白是结论，不是失败。**

⚠️ **同样是「没有」，意义相反**：

| | 意味着 | 怎么认出来 |
|---|---|---|
| **没顾上做** | 可能是机会——他们没空，你有 | 从来没人提过、也没人试过 |
| **做不到** | 可能是天堑——多少人试过都撞回来了 | 提交历史里试过又回滚、issue 里讨论过又关掉 |

**空白不都是机会，有些空白是别人替你踩过的坑。**

### 该不该自己跑一个

| 判据 | 结论 |
|---|---|
| 搜一下就有答案 | **不用跑**，去查 |
| 别人做过，只是我没找到 | **先去找** |
| **这道难题多年没解决** | **跑它**——不可能今天拍脑袋解决 |
| 输出清楚，却不知道拿什么喂它 | **跑它**——输入不清楚，正是实验的场合 |

要跑就去 `docs/experiments/` 开一个 `expNNN-<slug>/`：**假设 → 做法 → 结论 → 改变了哪一个取舍**。
**没改变取舍的实验，不值得跑第二个。**
