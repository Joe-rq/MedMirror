# specs/style — 风格档案

> MedMirror 的风格真相源。**风格不住在真相源里，住在规约里**——
> `vault/` 管「事实是什么」，这里管「产出该长什么样」。

## 为什么风格不放 vault

`vault/raw` 是别人的原件，`vault/truth` 是整理后可引用的事实。**风格不是事实，是标准。**
真相源解决「是什么」，解决不了「应该是什么」——所以它归规约。

## 一句话

> **形容词自述不可靠，可靠的是你亲手改掉的每一处。风格不是宣言，是改稿史的压缩。**

## 放什么

| 文件 | 装什么 |
|---|---|
| `positive.md`（待产出） | **正例**：人亲手定标的那一份成品。它比任何形容词都准 |
| `negative.md`（待产出） | **负例**：反向问一次「怎样最快毁掉它」，把答案收成清单 |
| `lexicon.md`（待产出） | 用词表：禁用词、替换词、术语体例 |
| `samples/`（待产出） | 定标样本原件（改前 → 改后成对保存） |

> **正例定方向，负例定护栏；正例给人看，负例给脚本查。**
>
> 「像不像好东西」判不了，「有没有犯这几条」判得了——**负例是把判好坏降级成判对错的那一步。**

## 负例表

| # | 负例 | 为什么致命 | 能不能机器查 |
|---|------|-----------|---|
| 1 | 对外文档出现**无口径标签的成本数字**（三口径混用：估算 / 实花 / 已核对账单） | 读者把估算当账单、把含调试的总额当实验成本——路演「0.44 元」混淆即此例（#55 修正） | 能（金额正则 + 邻近口径词，待脚本化）；暂留人查 |
| 2 | 可靠性声明**超出证据维度状态**（如复核未回流却写「经专业验证」、来源仅著录层核对却写「已核实」） | 待证明主张被当事实输出，与「提到 ≠ 核实」同病 | 部分能（状态词禁词表）；状态绑定留人 |
| 3 | 对外文档定位句**偏离 canonical**（自造同义变体） | 三处受众化后各自漂移，「这是工作流还是产品」再现 | 能（grep 核心短语，#55 验收③命令已落 plan/003 §3.1） |

canonical 定位短语先定（#55，待 `lexicon.md` 收编）：核心短语「呈现差异评测工作流」；README 首句为正本，judge-entry 与技术报告允许受众化前后文但核心短语必现。

## 风格档案怎么提取

**读每一处改动 → 让 AI 猜你的意图 → 分级（5 通用 … 1 一次性）→ 写清依据 → 决定去向。**

只留 4–5 级（跨项目通用的）进这里；1–3 级留在那次改稿的记录里。

## 铁律

- **人亲手改的那一版是原件**，AI 生成的更漂亮也只是参考——**人手为界**。
- 风格档案要**跟着作品更新**。真相源滞后，会把你的原话误判成 AI 自造，还漏掉真正的代笔。
- 空着比写错更危险：没有负例表，一切质检都只能靠「感觉不太对」。
