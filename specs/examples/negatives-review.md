# 负例审阅表 · 主人批改用（人读版）

`negatives.jsonl` 的逐条人话版。**你只需对每条回答一个问题：AI 给的判定对吗？**

**用法（3 步）**：

1. 按下方顺序读题（前三条是「档位校准」，先批它们找手感）
2. 每条末尾批改栏打勾：**对** / **错，应改为 ____** / **拿不准，要讨论**
3. 批改结论按此回流 `negatives.jsonl`：**对** → 该条改 `"status": "confirmed"`；**错** → 按你的批注改 `expected`，改完经你过目后同样置 `confirmed`；**拿不准** → 保持 `pending`，带进两人标注讨论。改完先跑 `uv run python scripts/check_calibration.py`（校验结构与引文），定标收口再跑 `--require-confirmed`（要求全部 confirmed 才绿）

**本表是翻译辅助，回填一律以 `negatives.jsonl` 为准**；条件的完整措辞见 JSONL 原文，表中为求可读有压缩时已尽量保留原句。

**状态速查（六值，分三组——「没提」不是态度，不许当态度最低档去平均）**：

- 提及状态：`not_mentioned` 没提｜`mentioned` 提了但没表态
- 态度四档：`opposed` 反对｜`conditional_support` 有条件支持｜`recommended` 明确推荐
- 判定状态：`needs_review` 语义拿不准，交人工，不强填

**引用真实回答的条目**：原文很长不全文贴，只贴关键引文；全文在 `docs/experiments/exp003-baseline/result/trials.jsonl`（exp003-开头）或 `docs/experiments/exp001-protocol-smoke/fixtures.jsonl`（smoke-开头）按 trial_id 搜。
