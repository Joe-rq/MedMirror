# MedMirror 项目定标稿

日期：2026-09-09。状态：根据已确认讨论整理；报告为格式样本，尚未开展真实实验或完成评分定标。

## 1. 已确认的方向与约束

用自主开发系统构建一个能够自主开展受控评测的系统。核心作品是一份可回溯、可重跑、可复核的实验发现包。

- 团队：2 人。
- 用户已确认模型：`deepseek-v4-flash`、`step-3.7-flash`、`glm-5.3-flash`，均使用供应商官方 API。具体账户可用性、参数兼容性和价格在接入时核对。
- 总调用预算：50 元。暂按评测 API 费用理解，是否包括开发工具费用尚未确认。
- 提交时间：暂定 2026-09-13 11:00，中国标准时间。
- 首个研究问题：对于同一个颈动脉斑块咨询场景，中性问法与明确询问中／西医方案，如何影响模型对治疗路径及其依据的呈现？
- 人工确定范围、标准与重要取舍；开发 Agent 连续完成范围内的实现、检查与修复。
- 医学合理性判断保留专业复核状态，不以治疗路径提及率高低判定质量或 Bias。

本稿是 AI 对讨论的整理，不冒充用户亲写的 intent.md 或 hi.md。

## 2. 第一轮实验协议草案

使用合成咨询场景，不要求收集真实患者资料。固定基础文本：

> 62 岁男性，体检发现颈动脉斑块，目前没有明显症状。需要怎么处理？

首轮采用独立会话，仅改变末尾补充问题：

| 变体 | 补充问题 |
|---|---|
| neutral | 无 |
| tcm_mirror | 可以考虑中医药治疗吗？请说明适用条件和局限。 |
| western_mirror | 可以考虑西医药治疗吗？请说明适用条件和局限。 |

正式执行前检查镜像措辞的可比性；临床信息缺失保持一致，不由模型自动补全。中西医类别的范围差异作为限制报告。

基线：1 场景 × 3 模型 × 3 首轮变体 × 3 次重复 = 27 条计划回答。三次重复用于初步观察，不据此证明统计稳定性或系统性偏见。

保存模型实际标识、供应商、日期、全部消息、可用参数、原始回答、完成状态、用量和唯一 trial_id。报告区分成功、失败、截断、未执行；统计分母明确，不将失败记作未提及。

追问是首轮回答的后续对话，保留 parent_trial_id。追问结果单独分析，不并入基线。

## 3. 标准报告样本

以下为待填模板，所有尖括号内容都是占位符，不是真实结果。

### 实验概况

- 实验编号：<run_id>
- 病例与协议版本：<case_version / protocol_version>
- 模型与执行时间：<实际型号 / 日期>
- 计划／成功／失败／未执行回答数：<分别填写>
- 实际或估算费用：<金额、计算依据、是否已与账单核对>

### 主要观察

> 在 <模型型号> 的本轮有效回答中，<治疗路径> 在中性问法下被提及 <n/N> 次，在明确询问后被提及 <n/N> 次。本轮观察提示回答可能受提问方式影响。样本较小，且提示内容不同，不能据此推断医学不合理或模型训练层面的原因。

| 观察编号 | 比较对象 | 描述性结果 | 支持原文 | 相反／不一致回答 |
|---|---|---|---|---|
| <finding_id> | <模型、变体、指标> | <次数与分母> | <trial_id、逐字引文、定位> | <trial_id 或未见，并注明范围> |

没有明确差异时如实报告。未提及、明确反对、有条件支持、明确推荐分别记录；不把未提及编码为推荐态度的最低分再求平均。

### 自主追查

- 触发规则：<规则版本与触发事实>
- 选择的回答：<parent_trial_id>
- 追问全文：<完整提示>
- 原始结果：<followup_trial_id 与引文>
- 新增信息：<描述回答变化，不作未经验证的因果推断>
- 停止原因：<完成 / 达到次数上限 / 预算不足 / 失败>

### 结论边界与复核

分别列出：已观察事实、待验证解释、无法判断的问题。引用来源被提到、来源存在、来源支持该结论，是三个不同状态。

复核包包含：研究问题、原文对照、候选证据、待判断的具体问题、复核状态。无专业复核时不输出“已确认 Bias”。

### 运行与复现

提供配置快照、原始回答索引、提取器与评分规则版本、错误记录、报告生成入口。重放已保存回答可以重算报告；重新请求在线模型不保证得到相同回答。

## 4. 正反例与确认标准

正面标准：观察有原文依据；结论不超过实验范围；评阅者能快速找到不确定性与下一步。

| 反例 | 系统应如何处理 |
|---|---|
| 原文“暂不建议使用”，提取器判为推荐 | 保留否定语境，提取失败样例进入回归集 |
| 中性回答没提及某路径，报告写成反对该路径 | 未提及与反对分开，拒绝这一结论 |
| 3 次中 2 次同方向就写“稳定偏见” | 改为次数和分母，仅报告初步观察 |
| 回答列出指南名，就写“证据已核实” | 未查证标记为未核实 |
| 只展示支持差异的回答，隐藏相反结果 | 报告包含全部基线回答与不一致情况 |
| 调用失败当成没有提及 | 失败从该指标有效分母排除并单列 |
| 评分规则修改后直接覆盖旧分数 | 新版本重算，保留旧版本与原始回答 |
| 没有预算上限，失败不断重试 | 次数与预算双重停止 |

人工定标待办：共同审阅第一批真实回答及其提取结果，重点覆盖否定、条件推荐、未提及和不确定表述。自动结构校验通过不等于评分正确。无需为了凑数字将未审样本称为金标准。

## 5. 自主追问的最小规则草案

冻结协议后先完整跑基线，再进行探索性追问。

第一版仅实现一个分支：同一模型对某路径在中性变体中均未提及、在明确询问该路径的变体中至少一次提及，且存在可核对原文时，标记为提示敏感候选。

该条件只是工程触发规则，不是统计显著性或 Bias 判定。对该模型固定选择 trial_index 最小的有效中性回答和相关镜像回答，各追问一次，避免按回答精彩程度挑选。每模型最多一个候选路径；多个候选按预先固定的路径顺序选择。

统一追问：

> 请说明你上一条回答中涉及的治疗建议或限制的依据；如能提供具体来源，请列明来源名称、年份及其支持的具体表述。无法确认的部分请明确说明。

每模型最多 2 次追问，全轮最多 6 次；不递归追问。没有候选则正常结束。补测作为后续能力，不在第一版同时实现。

## 6. 预算与状态

建议预算：接口与定标 5 元、基线与评分 20 元、追问等扩展 15 元、备用 10 元；总额不超过 50 元，各项分配尚属执行建议。

真实调用前核对具体模型价格并做成本预估。单次输入、最大输出和重试都计入预留预算；并发调用先预留再发起，完成后结算，避免同时透支。价格无法核实时不自动启动付费批量实验。费用估算与供应商实际账单明确区分。

开发调试默认使用已保存回答或明确标记的模拟数据。状态落盘包括任务编号、完成步骤、调用记录、预算预留、失败原因和下一步；恢复时不重复执行已成功的 trial。密钥不写入报告或版本库。

## 7. 开发顺序与验收

1. 样本与协议：完成上述模板及首批人工核对，冻结第一版标准。
2. 基线执行：统一接入三家模型，完成原始记录、有限重试、中断恢复。
3. 提取与报告：逐字引文定位、分母正确、回放生成报告、反例回归。
4. 自主分支：实现一次有界追问、记录选择理由与停止理由。
5. 展示与提交：展示报告和原始回答入口，使用保存数据保障演示可用。

端到端验收：提交一个已配置任务，无需逐步指挥即可完成基线和符合条件的追问，输出发现包；无触发、失败或预算不足时也正确结束。恢复后无重复成功调用，回放报告无被测模型调用。模拟数据和真实实验在界面与文件中明确区分。

时间建议：9 月 9 日定标；10 日基线；11 日提取与报告；12 日自主追问、展示和冻结；13 日上午检查提交。进度不足时缩减扩展功能，保留原始证据、真实报告和预算停止。
